# 提交前检查清单

项目代码和本地测试已经准备好。以下内容必须由两位结对同学在真正提交前按真实信息补充，不能由程序自动猜测。

## 博客需要补充

- 两位同学姓名、学号、博客链接。
- 本次作业博客发布后的链接。
- 最终 GitHub 仓库地址，仓库名按题目要求使用“第一个学号-第二个学号”。
- 两人的真实分工，不要直接照抄 `BLOG_DRAFT.md` 中的分工建议。
- 两人各自真实的队友评价与收获。
- GitHub commit 记录截图。
- 队友 fork 后的 Pull Request 截图。
- 单元测试 14/14 通过截图。
- 首页、发布页、详情页、“我的发布”和状态更新前后截图。
- `screenshots/04-core-flow.svg` 可作为博客中的关键流程图。

## GitHub 提交前

1. 一人创建符合命名要求的仓库。
2. 按功能拆分 commit，避免一次性只有一个大提交。
3. 另一位同学 fork 仓库，并在有真实修改后发起 Pull Request。
4. README 中的目录说明和运行方法保持不变即可。
5. 按课程要求决定是否上传 `tests/`；题目说明“单元测试不必上传”，但博客必须展示测试代码和结果。

## 最终运行检查

- Chrome 直接打开 `index.html`。
- 首页能看到 6 条演示数据。
- 搜索、筛选、详情、复制联系方式可用。
- 可以发布寻物和招领信息。
- “我的发布”中可以把寻物标记为“已找到”、招领标记为“已归还”。
- 双击 `run-tests.bat` 或执行 `node --test tests\store.test.js`，应得到 14/14 通过。

本清单只用于提交前自查，不需要放进博客正文。
