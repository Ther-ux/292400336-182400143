# 单元测试与测试报告

## 1. 测试工具

项目使用 Node.js 自带的 `node:test` 与 `node:assert/strict`。选择它的原因是项目本身是原生 JavaScript，使用内置测试工具无需安装 Mocha、Jest 等额外依赖，其他同学下载后只要有 Node.js 就能直接运行。

运行：

```text
node --test tests\store.test.js
```

也可以双击根目录的 `run-tests.bat`。

## 2. 我们如何学习并使用单元测试

一个最小的 JavaScript 单元测试包含三步：

1. `require('node:test')` 引入测试函数。
2. `require('node:assert/strict')` 引入断言。
3. 准备输入 → 调用被测函数 → 用 `assert` 检查输出是否符合预期。

示例：

```js
test('关键词可以命中物品名称', () => {
  const result = Store.filterItems(Store.seedItems, { keyword: '校园卡' });
  assert.ok(result.some((item) => item.title.includes('校园卡')));
});
```

如果断言失败，测试进程会给出失败用例和实际结果；修改代码后再次运行即可完成一次回归测试。

## 3. 白盒测试设计思路

我们先阅读核心逻辑 `js/store.js`，按主要分支设计测试：

- `validateDraft`：完整输入、缺少必填项、描述过短。
- `filterItems`：关键词为空/非空、按类型、类别、地点、状态筛选，以及组合条件。
- `updateStatus`：信息存在/不存在、本人/非本人、进行中/已解决。
- `statusText`：寻物解决后应显示“已找到”，招领解决后应显示“已归还”。
- 排序：搜索结果应始终按照发布时间从新到旧排列。

这种方法不是只走“顺利发布成功”的一条路径，而是覆盖了条件判断的不同结果。

## 5. 如何考虑测试人员“刁难”

除了正常路径，我们重点考虑了以下输入：必填项留空、描述只有两三个字、搜索不存在的内容、多条件组合后没有结果、搜索词前后有空格、英文大小写不同、非发布者试图修改状态、已经解决的信息再次更新。页面对没有结果和表单错误都有明确反馈，核心状态更新逻辑也有单元测试保护。
