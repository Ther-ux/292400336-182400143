# 拾光 · 校园失物招领

这是结对编程作业的 PC Web 实现。项目没有后端依赖，下载全部文件后，直接用 Google Chrome 打开 `index.html` 即可运行。

## 一、已实现功能

- 发布寻物信息和招领信息。
- 首页集中浏览全部失物招领内容。
- 使用物品名称、描述、地点、类别等关键词搜索。
- 按“寻物 / 招领”、物品类别、地点、处理状态筛选。
- 查看物品详情和发布者主动提供的联系方式。
- 一键复制联系方式。
- 发布者在“我的发布”中把寻物信息标记为“已找到”，把招领信息标记为“已归还”。
- 发布信息和状态变化保存在浏览器 `localStorage` 中，刷新页面后仍然保留。
- 空搜索结果、必填项缺失、描述过短等异常情况均有明确提示。
- 页面支持常见笔记本分辨率和手机宽度的响应式布局。

本次按题目要求，没有实现复杂后台、实名认证、即时聊天和地图定位。

## 三、运行方式

### 方式 A：按作业要求直接运行

1. 下载并完整解压项目。
2. 进入项目根目录。
3. 右键 `index.html` → 打开方式 → Google Chrome。
4. 无需安装依赖，无需启动服务器。

### 方式 B：双击启动

直接双击 `双击打开网页.bat`。脚本会优先寻找本机 Google Chrome，再打开 `index.html`。

## 四、测试方式

单元测试使用 Node.js 自带的 `node:test`，不依赖第三方测试框架。安装 Node.js 18+ 后：

```text
node --test tests\store.test.js
```

或者直接双击 `run-tests.bat`。

测试覆盖发布数据校验、关键词搜索、组合筛选、状态更新、发布者权限、排序等关键逻辑。详细测试说明见 `docs/TEST_REPORT.md`。

## 五、数据说明

首次打开时会自动展示 6 条演示数据，便于助教直接检查搜索、筛选、详情和状态展示。用户自行发布的信息会保存在浏览器本机的 `localStorage` 中，不会上传到网络。

如需恢复首次演示数据，可在 Chrome 开发者工具 Application → Local Storage 中删除 `campus-lost-found-v1` 后刷新页面。

## 六、核心流程

```text
发布信息
   ↓
首页集中浏览 / 搜索与筛选
   ↓
查看详情
   ↓
复制联系方式并线下联系发布者
   ↓
发布者进入“我的发布”
   ↓
寻物 → 标记“已找到” / 招领 → 标记“已归还”
   ↓
其他用户看到最新状态，减少无效联系
```

## 七、附加特点

1. **组合筛选**：关键词之外，可按类别、地点、信息类型和处理状态组合筛选，解决群聊里“看见过但找不回来”的问题。
2. **一键复制联系方式**：详情页可直接复制发布者联系方式，减少手抄出错；同时不引入即时聊天和账号系统，保持本次作业范围可控。

## 八、浏览器说明

开发与测试统一使用 Google Chrome。项目只使用原生 HTML、CSS、JavaScript 和浏览器标准 API，不依赖在线 CDN，因此离线打开也能展示预期结果。
